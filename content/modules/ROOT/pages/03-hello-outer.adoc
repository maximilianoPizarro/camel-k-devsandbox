Stop the Inner Loop first: *Inner — Stop* (`camel stop`).

[NOTE]

*What changes from the Inner Loop*

* *Inner:* logs appear in the `camel run` terminal.
* *Outer:* the operator creates pod `hello`; you read the same greeting in Topology → Logs.
====

== Same route, cluster deploy

The Outer Loop uses the same `labs/01-hello/hello.camel.yaml`. `scripts/up.sh` runs `platform.sh`, clears the previous lab, syncs the flow into `integration.yaml`, and waits for Ready.

[source,bash]
----
bash scripts/up.sh 01-hello
----

Or *Terminal → Run Task… → Outer — Hello*.

The first kit build can take several minutes (Maven downloads). Later builds are faster.

== What to look for

. Topology → Deployment `hello` → pod → *Logs*
. Line: `hello Hola desde Camel K en Developer Sandbox`
. Log also shows Apache Camel *4.22.0*

[source,bash]
----
oc get integration hello
oc logs -l camel.apache.org/integration=hello --tail=40
----

== Why a local IntegrationPlatform

Without one, kits publish into `camel-k-operator` and your pod hits ImagePullBackOff. `scripts/platform.sh` creates platform `camel-k` with OpenShift profile, S2I publish, and routine build strategy. See link:https://camel.apache.org/camel-k/2.11.x/installation/registry.html[Camel K registry].
